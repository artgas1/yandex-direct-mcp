## 1.0.0 — 09.09.2026

Первый выпуск. MCP-сервер и командная строка к API Яндекс Директа v5.

### Покрытие

**30 служб, 113 методов, 604 типа, 235 перечислений** — порождены из
машиночитаемой схемы, ни один метод не описан руками. Читающих 33, меняющих 64,
удаляющих 16.

Источников два, и роли разделены замером, а не вкусом: WSDL даёт состав и типы
(в индексе документации нет служб `vcards`, `smartadtargets`,
`dynamictextadtargets`, `dynamicfeedadtargets` — по нему спека вышла бы
неполной, и неполнота была бы невидимой), документация даёт описания (в WSDL нет
ни одного `xs:documentation`). Служба `reports` описана явно: WSDL для неё
Директ не отдаёт.

### Что сервер закрывает

Каждый пункт снят прогоном живого кабинета, а не прочитан в документации.
Общее у них одно: без сервера ошибка происходит **молча** — ответ выглядит
нормальным, отказа нет, а число или вывод неверны.

- **Суммы приводятся к валюте счёта.** API отдаёт деньги умноженными на миллион
  всегда: `DailyBudget.Amount = 1000000000` — это 1000 единиц валюты счёта. Заголовок
  `returnMoneyInMicros` действует только на отчёты; на обычные службы — нет
  (проверено). Пересчитанные поля перечисляются в ответе.
- **Длинные идентификаторы сохраняются точно.** `Id` объявления
  `1234567890123456789` — девятнадцать цифр; `JSON.parse` даёт
  `1234567890123456800`. Проверено на нескольких рекламных кабинетах: такие
  идентификаторы встретились в каждом; в схеме 358 полей объявлены типом `xsd:long`. Испорченный идентификатор Директ принимает и отвечает
  `HTTP 200` с телом `{"result":{}}` — то есть «объявления нет» вместо отказа.
- **Успех определяется телом, а не кодом.** Ошибка приезжает с 200 (код 8000),
  с 202 (код 55) и с 400 (код строкой `"8000"`), а у отчётов 201 и 202 означают
  «ещё считается».
- **Отчёт дожидается.** 201 → 202 → 200 с повтором по тому же `ReportName`.
- **Версия пути учитывается.** По `v501` кампании приходят с
  `Type=UNIFIED_CAMPAIGN`, по `v5` те же — с `TEXT_CAMPAIGN`; несовпадение
  версии и набора глубоких полей отнимает стратегию и настройки без ошибки.
  Умолчание `v501`, версия печатается в каждом ответе, несовпадение вызывает
  предупреждение.
- **Обёртка `Items` ставится и снимается по графу типов**, а не по виду
  значения: `RegionIds` (`maxOccurs=unbounded`) — голый массив,
  `RestrictedRegionIds` (`ArrayOfLong`) — `{"Items": […]}`, и это одинаково в
  обе стороны.
- **Итог поэлементных операций разбирается по `Errors`**, а не по наличию
  содержимого: `Warnings` означает «применено с замечанием».
- **Фактический кабинет называется в каждом ответе.** `Client-Login`
  переключает кабинет по-настоящему (проверено: под одним токеном заголовок
  отдаёт другой аккаунт, со своими кампаниями и своей квотой баллов). Неверный логин
  отбивается кодом 8800, а верный, но не тот — молча отдаёт чужие данные,
  поэтому сервер спрашивает у API, кто отвечает.
- **Состав кабинета собирается из двух источников.** Инструмент
  `direct_inventory` склеивает список кампаний и отчёт, помечая каждую строку
  источником. Кампании Мастера кампаний не отдаются `campaigns.get` вовсе, и
  ответ при этом успешный и пустой — отличить «нет такой» от «не показывается»
  нечем. Прогон на живом кабинете: объединение оказалось на кампанию длиннее
  списка, и эта строка была видна только отчёту — такая кампания может нести
  основную долю показов.

### Поверхность

| профиль | инструментов | байт `tools/list` |
|---|---|---|
| `core` (умолчание) | 13 | 27 028 |
| `read` | 37 | 61 158 |
| `all` + запись | 117 | 143 706 |

Вложенные типы в схемы не разворачиваются: транзитивно `campaigns.add` это
1083 поля и 54 КБ на один инструмент. Состав типа назван словами, точная схема
выдаётся инструментом `direct_schema` по запросу.

### Безопасность

Изменение выключено по умолчанию: меняющие инструменты не объявляются вовсе,
пока не задан `DIRECT_ALLOW_WRITES=1`. Неизвестный профиль — отказ на старте,
а не откат к полной поверхности. Есть песочница `DIRECT_SANDBOX=1`, факт
включения печатается при старте и в каждом ответе.

### Проверки

48 тестов, включая отрицательные контроли на порчу идентификатора, на ошибку с
кодом 202, на пустую схему `get`, на пропажу службы и на чтение предупреждений
как отказов. Сквозной прогон собранного сервера против живого API —
`npm run smoke`.

### Известные оговорки

- Перечисления из схемы отстают от живого API (`campaigns` принимает
  `CreateTime`, `keywords` — три значения автотаргетинга, которых в WSDL нет),
  поэтому они идут подсказкой в описание, а не жёстким фильтром.
- Описания 31 метода собраны из схемы: страниц документации для служб `vcards`,
  `smartadtargets`, `dynamictextadtargets` и `dynamicfeedadtargets` Яндекс не
  публикует ни на русском, ни на английском.
